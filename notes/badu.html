参考契约八维度清单

可打勾的八维度表：把「找重点」换成「逐条回答」　·　方法论 · 公开版

用途：给一个参考实现 + 一个要写的新实现，逐维度填「参考怎么做的 / 我打算怎么做 / 是否故意不同」。 为什么需要固定清单：自由发挥的「找重点」有个致命缺陷——你不知道你不知道什么。没注意到的维度，清单里根本不会出现，于是漏得无声无息。固定维度表把「主观找重点」换成「逐条回答」，漏了就是一行空白，看得见。

配套理论见 参考实现的契约提取（复位者判据、契约表、性质测试）。本文只是可打勾的版本。

一、使用方式

  1. 动手写第一行实现代码之前，把下面八行抄成表，逐行填。
  2. 任何一行填不出来 → 说明还没读懂参考实现，去读，不要开始写。
  3. 填完把表存到 docs/参考契约/<案例名>.md，随代码一起留下。只活在对话里的差异清单，下一个人（或下一个 agent）会从零重来。
  4. 第 3 列填「有意」或「未察觉」。不许填「无差异」——填了说明根本没找。

二、八维度

# 维度 问法 为什么危险 反例（本机真实）
1 求值时机 这个值在什么时候算出来？读时 / 写时 / 构造时 / 定时 同一份数据，求值位置不同 → 自愈能力完全不同 参考 isFrozen() 读时比时间戳（自愈）；自己实现在写时算好并靠 tick 复位（不自愈）
2 驱动者 谁推动状态前进？把这个驱动整个删掉，性质还成立吗 驱动一停就永久卡死，且现场看不出异常 tickServer 不跑 ⇒ WAITING 永不为空 ⇒ blocksWorldTick() 恒 true ⇒ 世界永久冻结
3 生命周期终点 谁负责复位 / 清理 / 释放？没人负责就是泄漏 泄漏型 bug 潜伏期长，发作时与起因隔了很远 到期只靠驱动复位，驱动不在就没人复位
4 判据位置 准入或拒绝的判断读的是哪个字段 / 哪个方法 判据读错字段 → 放行了本该拦的，或拦了本该放的 「放行」与「生效」是两件事，见 1.18.2 Forge API 事实速查 §九
5 失败方向 出错时是保守（拒绝）还是激进（放行）？两处必须一致 一处保守一处激进 → 出错的边界上行为不可预测 校验失败时静默降级为「允许」
6 作用域 全局 / 每玩家 / 每世界 / 每实例；会不会跨作用域泄漏 静态字段装每玩家状态，多人时互相污染 —
7 顺序与重入 重复调用是否幂等？并发或递归调用是否安全 非幂等的初始化/累加在重试或重入时翻倍 —
8 默认值语义 null / 0 / 空集合 / 缺省字段分别意味着「没有」还是「不限」 把「没有」当「不限」→ 无条件放行 配置缺省即全开

三、反向验证（唯一能机械检测「漏抄」的办法）

正向测试测的是「我的实现对不对」，测不出「我有没有漏掉参考实现的性质」。

做法：把参考实现故意改坏，看你的测试红不红。

把参考实现的「读时求值」改成「写时求值 + 靠 tick 复位」
  → 如果你的测试仍然全绿，说明测试根本没覆盖到那条性质，你确实漏了
  → 如果变红，说明这条性质被你的测试抓住了

判据：测试必须在「参考实现被改坏」时失败，否则它不是契约测试，只是实现快照。

四、维护规则

  • 踩到新坑就往八维度表里加一行，不要追求一次写完备。成本随经验摊薄：一次性建表，之后每次失败只付一行。
  • 某个维度在本项目反复出问题 → 在「为什么危险」里补一条本机反例，让人一看就知道疼在哪。
  • 维度表只放跨语言跨领域恒真的问法；项目专属细节放项目自己的 docs/已验证结论.md，这里只留一行指针。
  • 这张表不保证 100% 覆盖，只覆盖已知的语义维度。发现它漏了，就说明出现了新类型的坑，加行。
